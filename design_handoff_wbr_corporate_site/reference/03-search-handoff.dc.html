Hero Search and the Conference Finder

How the homepage search suggests events as you type, and how it hands off to the full conference finder at /conferences. Both surfaces use one search endpoint and one set of URL parameters, so a search on the homepage and a filtered finder page always return the same events.

02 · The flow

From Homepage Search to Finder

Step 1

Focus

Dropdown opens with popular searches and the next three events. No request needed; this list ships with the page.

Step 2

Type

At 2+ characters, wait 150ms after the last keystroke, then call the search endpoint with limit=5. Cancel any earlier request still in flight.

Step 3

Suggest

Show up to 5 events, best match first, with the matched text highlighted. Last row is always "See all N results".

Step 4a · Pick an event

Click or Enter on a highlighted row opens that event's own site (e.g. etailboston.wbresearch.com) in the same tab. The finder is skipped.

Step 4b · See all / Enter

Navigate to /conferences?q=retail. The finder reads the parameters on load, fills the keyword field, shows the pill and filters the list. Every later filter change rewrites the URL.

Source of truthThe URL. The finder UI is a view of the query string: read it on load, write it on every change. Never keep filter state only in memory. HistorypushState when arriving from another page (homepage → finder). replaceState for filter changes on the finder, so Back returns to the homepage in one step rather than undoing each filter. ReturningBack from the finder restores the homepage with the last query still in the search box.

04 · URL parameters

The Finder's Query String

All values are lowercase slugs. Leave out parameters at their default so /conferences is the clean, unfiltered page. Ignore unknown parameters and invalid values rather than erroring.

toYYYY-MM. If earlier than from, swap them.current month + 11To month + range pill?to=2027-06

06 · Behaviour rules

What to Build

Matching

Search event name, brand, city, country, sector and type. Case- and accent-insensitive. Match the start of any word, and allow one typo for queries of 5+ characters ("procurment" finds ProcureCon). Only upcoming events.

Ranking

1. Name starts with query. 2. A word in the name starts with query. 3. Name contains query. 4. City, then sector, then type, then region match. Ties go to the soonest date. When the match isn't in the name, show why ("City match").

Timing

Minimum 2 characters. 150ms debounce. Cancel in-flight requests when the query changes. Only show the loading skeleton if the response takes over 300ms, to avoid flicker. Cache responses per query for the session.

Keyboard

↓ / ↑ move through rows, then "See all", and wrap. Enter opens the highlighted row, or goes to the finder when nothing is highlighted. Esc closes the dropdown; a second Esc clears the field. Tab closes and moves on.

Accessibility

Input: role="combobox", aria-expanded, aria-controls, aria-activedescendant. Dropdown: role="listbox", rows role="option". A polite live region announces "5 events found".

Mobile

On focus below 768px, open search as a full-screen sheet with the input pinned at the top and a Cancel button. Rows keep a 56px minimum height. Finder filters collapse into a "Filters" button that opens a bottom sheet.

Analytics

search_suggest_shown {q, count} · search_suggest_click {q, event_id, position} · search_see_all {q, count} · search_no_results {q} · finder_filter_change {param, value}.

Finder Filters

Filters combine with AND. The keyword field updates the URL 300ms after typing stops. Each active filter shows a pill; removing a pill resets that parameter. "Clear all" returns to /conferences.

Empty and Error

No results: say so with the query, offer popular searches, keep "See all" so the finder can suggest wider filters. Network error: hide the dropdown; Enter still goes to the finder, which renders server-side.

07 · API contract

One Endpoint for Both Surfaces

The dropdown calls it with limit=5; the finder calls it with the full query string and no limit (or paged). Same matching and ranking either way, so the "See all 12 results" count equals the finder's count.

Request
GET /api/events/search?q=etail&limit=5

# finder
GET /api/events/search?q=etail&region=americas
    &type=conference&from=2026-10&to=2027-09
    &sort=date
Response
{

  "results": [{
